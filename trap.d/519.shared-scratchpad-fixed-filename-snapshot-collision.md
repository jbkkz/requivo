Observed in lane #519 on 2026-09-12: the self-review phase file (`agents/developer/review.md`)
shows the tree snapshot held in a shell variable, `BEFORE=$(... snapshot)`, and piped back into
`compare` later. A shell variable does not survive between Bash calls in this harness, so I
persisted it to the session scratchpad -- under the fixed name `before.json`. Between the spawn and
the compare, a sibling lane (fix/493) wrote its own `before.json` to the same directory: the
scratchpad path the harness hands out is shared by every concurrently running lane, not per lane.
`compare --before` then reported `mutated -- HEAD moved from ceff80e... to 912264c...`, two commits
that belong to the 493 worktree, and the receipt for my own reviewers' non-mutation was lost.
Recovered by reading `git reflog` and `git status --untracked-files=all` in my own worktree (only
my commits and amends; clean tree), which is reasoned evidence and not the receipt. Cost: one
round-trip to diagnose, and a `could-not-compare` in the report where a `clean` should have been.

The report phase file (`agents/developer/report.md`) does say this -- "a fixed filename under the
shared scratchpad is a real collision" -- but it is read at report time, after the snapshot has
already been taken; the review phase file, which is where the snapshot is written, says nothing
about persisting it. A one-line note there ("if you must persist `$BEFORE`, name the file by branch
and timestamp; the scratchpad is shared across lanes") would have prevented it. The directory listing
also showed a second lane had already learned this the hard way (`before_530.json`,
`before-425b-slice4.json`) beside the bare `before.json`. Unsure whether this is a jit-context rule
or an edit to review.md; logging it for the curator.
