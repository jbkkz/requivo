Observed twice in one lane (#258), both on the first attempt at a supertool write payload.

The brief says a TOML triple-single-quote literal block processes no escapes and to write the bytes
wanted on disk. I read it, and still wrote a Python `"\n\n"` string as a doubled-backslash form in a
payload -- once in a test file (`paste`), once in `SHARED_PROMPT_HEAD` in `core/context.py` (`edit`).
supertool refused both with its even-run backslash detector (#2314), which named every occurrence and
offered the two opposite fixes, so nothing wrong reached disk. Cost: two full re-sends of a 180-line
and a 60-line payload, plus the refusal text re-read each time.

The refusal opens `ERROR: @file payload refused (<stdin>): a [triple-single-quote] literal block
carries an EVEN run of backslashes` -- the delimiter is spelled out here rather than quoted, because
a third trap fired twice on this very file: quoting that refusal verbatim put a triple-single-quote
run inside a triple-single-quote block, which closed the block early (`bad key at offset 184`, then
`expected '=' after the key at offset 802`, #1830). The second time I had already moved the run out
of one sentence and left it in the next.

What the reflex actually is: when the target is a `.py` file and the content is a Python string
literal that needs a newline escape, the hand types the escaped-in-a-string form (two backslashes)
because the outer container "feels" like a string too. The rule "one backslash means one backslash
on disk" is stated in the brief; what it does not say is that the trap fires specifically on Python
string literals inside a payload, where a single backslash-n is both correct on disk and correct for
Python.

Confirmed by re-sending with single backslashes; both validators passed and the tests read the
constant correctly. Unsure whether this is already covered by a jit-context rule -- the brief's
paragraph reads as the same rule -- but it did not stop the reflex, so the phrasing may want the
concrete `.py`-string case, and the delimiter-in-content case beside it (which the refusal text
itself provokes, since it names the delimiter and a lane quoting the refusal re-sends it).
