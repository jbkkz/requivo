Observed on #425 slice 4, writing `tests/api/test_api_auth.py`'s constant-time probe.

The test wanted to assert *which function decides* the bearer comparison, so it did
`monkeypatch.setattr(auth.hmac, "compare_digest", probe)` and had `probe` call
`hmac.compare_digest(a, b)` to preserve behaviour. `auth.hmac` is the stdlib `hmac` module object
itself, not a copy, so the patch replaced `hmac.compare_digest` globally for the test, and the
probe's own call to `hmac.compare_digest` resolved to the probe:

    RecursionError: maximum recursion depth exceeded
    !!! Recursion detected (same locals & position)

Cost: one failed run and one edit (capture `real = hmac.compare_digest` before patching, call
`real` from the probe). Confirmed by re-running the file: 53 passed.

The general shape, if it is a rule at all: patching `<module_under_test>.<stdlib_module>.<name>`
patches the stdlib module for everyone, including the probe -- capture the original before the
`setattr`, or patch a name the module under test bound at import (`from hmac import
compare_digest`) so only that module sees the probe. Unsure this is worth a jit-context rule; it is
the ordinary "capture before you patch" reflex, logged because it cost a round-trip here.
