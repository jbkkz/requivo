- Every document generator now reads the client's original request beside the model (#782), fenced as untrusted client data, instead of the model alone. Each document prompt (brief, PRD, stories, criteria, estimate, epic, release notes, go-to-market plan) carries one shared rule on the client's words: an inferred topic reads as an assumption, the client's silence never confirms anything, an actor, role, constraint or number the client did not give is presented as a proposal, and an ambiguous answer says which reading the document took. The Claude Code plugin's shared reasoning rules carry the same sentence.
- The estimate now sees the model as well as its stories (#782). A high-impact topic the model states (What or How) that no story traces to is uncovered: the estimate's confidence can no longer read `high` while one exists, `estimate.md` and the terminal name it under "Not covered by any story", and the API's estimate `artifact` gains an `uncovered` list.
- `ReasoningProvider.generate` gains an optional `request` keyword, which `DiscoveryService` always passes; the estimate's return shape is unchanged (#782).
- Compatibility: compatible - the protocol keyword is optional and `**kwargs` already carried per-artifact options; `uncovered` is an added key; an estimate that read `high` with a stated topic outside every story now reads `medium`.
