- The Claude Code plugin's shared preflight (`REASONING.md`) now offers to install the `requivo` CLI itself, instead of only telling the user what to type — and every one of the ten skills' own missing-CLI lines now delegates to that one flow instead of each separately instructing Claude to stop, which had left the new offer unreachable from every skill, `/requivo:run` included. Detection is unchanged — the `requivo doctor --json` probe and its shape-not-wording rule still decide whether the CLI is missing — but a missing CLI now branches into an offer before falling back to the four-things message: it names every command before running it and routes by what is actually on the machine. `uv tool install requivo` when `uv` resolves, `pipx install requivo` when only `pipx` does, and — since the README no longer tells anyone to install a package manager first — `curl -LsSf https://astral.sh/uv/install.sh | sh` to get `uv` followed by `uv tool install requivo` when neither is present, so a fresh machine reaches a working install rather than a command it cannot run. `pip install --user` is never offered on any route, because it leaves `requivo` off the `PATH`. Whichever route is offered, a yes runs it and re-probes rather than trusting an installer's exit code, then continues the skill the preflight interrupted so the user does not have to re-issue their request; a no, any command that fails, or `uv` still not resolving after the bootstrap step all fall through to today's four-things message, byte-for-byte unchanged. `README.md`'s Claude Code door drops from six steps to four, all of them typed inside Claude Code — the `uv` prerequisite and its `uv tool install requivo` step leave that door, because the preflight now picks the route on every machine shape; `plugins/claude-code/README.md` describes the same sequence (#573).
