- The software schema gains `payer` (*Why?*) and `acquisition` (*Validation*) for requests that are product ideas rather than specs (#775): who pays and how, and how the first users are reached. Both are required with a low default impact, raised to high when the request is a builder's own product, so an internal tool leaves them as assumptions while a product idea cannot read as ready without them. `/requivo:run` now recommends the `go-to-market` perimeter, with its reason, when a request asks whether something is worth building or who it is for; the user still chooses.
- Compatibility: compatible - a software session written before this change still loads; both slots read at their low baseline and never block it. A software proposal without them is refused by `model apply`/`model diff` as `missing_required_slot`, the same moved observable as #786.
