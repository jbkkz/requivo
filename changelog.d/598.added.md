- When a first `requivo discover`'s grounding judgment (#593) says `uncovered` — the request's
  domain carries constraints material to the solution and no installed card describes it — the
  engine now **writes the missing card** instead of only warning: one more cheap provider call
  fills a typed `GeneratedCard` (fields only, never raw Markdown), a deterministic writer renders it
  into `assets/context/_template.md`'s own section shape, and the empty session this call just made
  is re-claimed selecting that card alone. The other installed cards are irrelevant to this domain,
  and removing them from the reasoning is the whole point (#598).
- The generated card is written into `<workspace>/.requivo/context/`, a third root `_card_paths()`
  now reads alongside the bundled and user-installed ones — an ordinary card from then on, so
  `--context`, `render_grounding`, `doctor`, `session verify` and `session rescope` all work on it
  for free, and it is reusable by every later session in the same workspace without being written
  twice (#598).
- Cost: on the `uncovered` path, a first discovery with no `--context` now makes a **third** provider
  call (judgment, card, discovery turn) rather than two. A provider that cannot write a card, or a
  generated stem that collides with an existing one, falls back to the report-only warning #593
  shipped rather than failing the discovery (#598).
- A stem collision is refused, never silently shadowed: a generated card whose name already resolves
  to an installed or previously-generated one is rejected rather than overwriting it (#598).
- Promotion of a workspace-generated card into the shared `user_context_dir()` is deferred, not
  built in this change — see `decision: the-engine-writes-the-missing-card` for the shape and the
  trigger (#598).
