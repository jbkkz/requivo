- `DiscoveryService.claim_and_ground`'s return value is now a `ClaimAndGround` NamedTuple (`meta`,
  `grounding`, `cards`, `routing`) rather than a bare tuple, so a fact added to it later costs an
  attribute rather than another break for every caller that unpacks (#601).
- Compatibility: breaking - `claim_and_ground` returned three positional values before this lot of
  changes and now returns four (the perimeter router's own verdict, `routing`, joins the three
  #593 already returned); a caller still unpacking the original `meta, grounding, cards = ...` now
  raises `ValueError: too many values to unpack`, at the worst possible point — after the provider
  calls and the session mutations. `DiscoveryService` is part of the declared Python import seam
  (`docs/compatibility.md`), and this break is priced into 4.0.0 (#607). Read the return by
  attribute, not by position, going forward.
