- A slot can now label the statements it holds (#751): an optional `claims` list, at most eight, each with its `text`, where it came from (`source`: `requester`, `artifact`, `evidence`, `proposed`, `domain`, `assumed`), what an answer did with it (`confirmation`: `open`, `let_stand`, `confirmed`, `to_test`), who answered, and an `impact` that may sit below its slot's but never above it. A malformed claim is refused rather than repaired, so it rides the retry loop. The engine prompt and the Claude Code plugin emit claims only on a slot that mixes provenance — a stated limit beside assumed obligations — and `DesignDecision` gains an informational `source` (`requester` | `proposed`), which the decision brief now fills.
- Claims are informational in 3.x: readiness, the understanding groups and the defaults list still read the slot's `confidence`. `requivo status` shows each slot's claim mix and counts the claims rated below their topic's impact; `model apply` and `model diff` name the claim that moved (`changed_claims` in `--json`), as does the checkpoint after each answer; `status --json` gains `claims_below_slot_impact` and a `claims` list on each `understanding` entry. A moved claim counts as a material change to its slot, so the artifacts resting on that slot go stale. The decision record is `docs/decisions/0025-claims-carry-provenance.md`, amending 0021.
- Compatibility: compatible - optional fields, absent on disk until set (a claimless session is written exactly as before, and `format_version` stays 1), plus added `--json` keys; a 3.x reader carries claims through a re-save as unknown keys, and a Requivo older than this one refuses a proposal carrying `claims` or a decision `source` as an extra input.
