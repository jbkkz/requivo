- `requivo impact` now says what to change, not only what is stale (#810). Under each stale document it names the slots you asked about that the document consumes, with every material field that moved since the revision the document was written from (its value, and its confidence, impact or test plan when those moved), plus the claims that moved in them (#751). So one rule is patched instead of five documents regenerated, and a slot that made a document stale never reads as unchanged. The same report is `stale_changes` in `impact --json`, the `/impact` API route and the MCP `get_impact` tool: one `{artifact, revision, slots, claims}` per stale document, each slot as `{slot, label, before, after, moved}`, with `before` set to `null` when that revision cannot be read.
- Compatibility: compatible - one added `--json` key, `null` for a bare `model.json` (`docs/compatibility.md`); every existing key keeps its meaning.
